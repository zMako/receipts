# E-commerce Returns Abuse, Refund Fraud and Chargeback Disputes in 2026 — and How AI Agents Are Changing Them

Research date: 2026-10-03. Figures are dated inline. Scope: material a builder needs to design a merchant-side "returns-abuse and dispute screener" agent.

---

## Key Question 1: Size of the problem (return rates, fraud/abuse dollars, chargeback volumes and win rates, friendly-fraud share)

### Takeaway
US retail returns run ~$850B/yr (15.8% of sales; 19.3% online) with roughly 9–15% of returns fraudulent or abusive and ~$100B+/yr in fraud-and-abuse losses; on the dispute side, friendly fraud is the majority of chargebacks, merchants win ~45% of what they fight but net-recover only ~11%, and both Visa and Mastercard dispute volumes are rising (Mastercard +41% 2023→2026).

### Cited Findings

**Return volume and rates**
- NRF/Happy Returns "2025 Retail Returns Landscape" (published Oct 15, 2025; survey summer 2025, n=2,006 consumers + 358 retailers with $500M+ revenue): overall return rate 15.8% of annual sales = $849.9B; online return rate 19.3%; holiday return rate 17%; 2024 comparison was 16.9% / $890B — [NRF press release](https://nrf.com/media-center/press-releases/consumers-expected-to-return-nearly-850-billion-in-merchandise-in-2025); [NRF report page](https://nrf.com/research/2025-retail-returns-landscape)
- Gen Z (18–30) averaged 7.7 online-purchase returns in 12 months; ~two-thirds of consumers admit to costly return behaviors (wardrobing, bracketing); 45% think "bending the truth" on returns is acceptable; 82% say free returns are important (up from 76% in 2024); 76% want instant refund/exchange — [NRF press release](https://nrf.com/media-center/press-releases/consumers-expected-to-return-nearly-850-billion-in-merchandise-in-2025)
- Loop Returns 2026 Global Ecommerce Retention Report (23.4M returns, 4,000+ Shopify merchants, Nov 1 2024–Oct 31 2025): 11.4% of return value flagged high-risk; average fraudulent return value $120; 65.2% of merchants charge fees on at least some returns (avg $9.04); avg refund window 39 days, exchange window 41 days; 73.6% offer exchanges; 49.2% offer "Shop Now" — [Loop Returns](https://www.loopreturns.com/reports/retention-benchmarks-2026/)
- Apparel average return rate ~25%, some fashion sub-segments 40–50%; bracketing practiced by 63% of online shoppers (Loop research, as summarized) — [Trackvid summary of Loop data](https://trackvid.in/blogs/ecommerce-return-statistics.html)
- PYMNTS (Mar 3, 2026): "nearly $1 trillion" returned in 2024 (note: conflicts with NRF's $890B for 2024 — NRF is the primary source); retailers spend ~$200B/yr recovering value from returns; refund fraud = 1–2% of total sales dollars; "nearly 1 in 4 refund dollars are linked to abusive behavior" (Riskified analysis) — [PYMNTS](https://www.pymnts.com/news/retail/2026/ai-generated-damage-claims-trigger-retail-crackdown-on-return-fraud/)
- E-commerce returns expected to cost brands $379B in 2026; fraudulent returns >$100B annually — [Modern Retail, Mar 2, 2026](https://www.modernretail.co/technology/from-boll-branch-to-bogg-brands-are-battling-a-surge-of-ai-driven-return-fraud/)

**Fraud and abuse share**
- NRF/Happy Returns 2025: 9% of all returns are fraudulent; among retailers tracking it, increases reported in overstated quantity of returns (71%), empty box / "box of rocks" (65%), decoy returns such as counterfeit items (64%); 85% of retailers use AI to detect/prevent return fraud — [NRF press release](https://nrf.com/media-center/press-releases/consumers-expected-to-return-nearly-850-billion-in-merchandise-in-2025)
- 2024 NRF/Appriss Retail: $890B returned, return fraud and abuse $103B (as summarized in search results citing NRF/Appriss) — [Retail TouchPoints](https://www.retailtouchpoints.com/features/news-briefs/nrf-forecasts-nearly-850-billion-in-returns-in-2025-slight-decrease-from-2024); Ravelin and LiquiDonate both cite $101B/yr in US returns fraud and abuse (2024, up 20% YoY per LiquiDonate) — [Ravelin](https://www.ravelin.com/blog/refund-abuse-return-fraud); [LiquiDonate via Yahoo Finance, Jan 2026](https://finance.yahoo.com/news/liquidonate-shares-uncomfortable-reality-check-203235213.html)
- LiquiDonate 2026 Returns Fraud Report (Jan 2026): estimates 15% of all returns are fraudulent; 85% of surveyed retailers experienced return fraud; 1 in 3 consumers admits at least one form of return fraud; $13.70 lost per $100 returned (2023 NRF); $25–30 processing cost per returned item; 6–10 days processing time; 13–70% of shoppers admit wardrobing (wide range, survey-dependent) — [Yahoo Finance](https://finance.yahoo.com/news/liquidonate-shares-uncomfortable-reality-check-203235213.html)
- Ravelin: 60% of item price lost per fraudulent return; 78% of merchants say fraud has stifled growth (2026 report); "refund abuse just outranked traditional forms of first-party abuse" in merchant impact — [Ravelin](https://www.ravelin.com/blog/refund-abuse-return-fraud)
- Ravelin 2026 report (as summarized): 1 in 4 shoppers admitted abusing refund policies in the prior year, 98% of them succeeded; >80% of fraud attacks on retailers now use AI — [Home of Direct Commerce](https://homeofdirectcommerce.com/news/80-per-cent-of-retail-fraud-uses-ai-and-returns-abuse-rising/)
- Riskified/eTail Insights survey (released Jun 22, 2026; n=2,091 consumers, 7 countries, US 51%, UK 14%, Japan 12%; plus 10 interviews with retail leaders at $250M–$10B brands): 50% use generative AI (ChatGPT, Claude) to help draft return/refund claims; 85% accept at least one strategic/deceptive return behavior as normal; 46% say returning items that "look different" is fine; 42% bracket; 24% say wearing an item before returning is acceptable; >50% have seen return "life hacks" on social media; 52% support stricter policies; 56% prefer tiered/personalized policies — [StockTitan mirror of Riskified release](https://www.stocktitan.net/news/RSKD/return-abuse-goes-mainstream-as-nearly-half-of-consumers-use-ai-in-zigrxun82sxl.html); [BusinessWire original](https://www.businesswire.com/news/home/20260622536790/en/Return-Abuse-Goes-Mainstream-as-Nearly-Half-of-Consumers-Use-AI-in-Return-Claims-New-Riskified-Research-Finds)
- Signifyd report (as cited by Ringly): 62% of consumers admit to at least one abusive return behavior; US return fraud $127B in 2025 (~15% of returned merchandise) — [Ringly](https://www.ringly.io/blog/how-can-i-prevent-refund-fraud-on-shopify)
- Empty-box returns: 65% of retailers reported them in 2025, 55% report YoY increase; one Lululemon empty-box scheme reached $200,000 over 12 months before arrest (as summarized) — [RefundSentry](https://refundsentry.com/return-fraud)

**Chargebacks**
- Chargebacks911 2026 Chargeback Field Report (published Jun 30, 2026): merchants win 44.6% of chargebacks they represent, but net recovery rate is only 10.7% (second-cycle disputes, undetected fraud); 83.4% of merchants reported an increase in friendly fraud; merchants estimate friendly fraud at 43.8% of chargebacks vs. "considerably higher" industry data; 34% use Ethoca/Verifi alerts; 33% use 3-D Secure; 27% use AI-based detection, 37% plan to; 69% rely solely on in-house staff for representment — [Chargebacks911 stats page](https://chargebacks911.com/chargeback-stats/); [Field Report](https://chargebacks911.com/chargeback-field-report/)
- Mastercard: global chargebacks rose 41% from 238M (2023) to 337M (2026); $37.07B of disputes filed in 2026, ≈$170.89B in losses with cost multiplier — [Chargebacks911 stats](https://chargebacks911.com/chargeback-stats/)
- LexisNexis 2026: every $1 lost to fraud costs US merchants $5.13 (+52.6% vs 2020); avg 5.1 chargebacks per cardholder at $84 each in 2025 — [Chargebacks911 stats](https://chargebacks911.com/chargeback-stats/)
- Friendly fraud ≈79% of chargebacks; historical merchant win rate on friendly fraud 15–20%; CE 3.0 submissions win 40–60% depending on category and device-intelligence quality — [cside](https://cside.com/blog/what-is-friendly-fraud)
- Stripe: "Fraudulent disputes account for over half of all disputes"; Radar win-likelihood prediction maps to expected win rates of 5% / 15% / 25% / 40% / 60% (1–5 dots) — "Even in the most favorable cases, it's very difficult to overturn a disputed payment" — [Stripe docs](https://docs.stripe.com/disputes/best-practices)
- Vendor claim: Chargeflow says its automated customers win ~75% vs a 12% industry average (unverified vendor marketing) — [Chargeflow](https://www.chargeflow.io/blog/visa-compelling-evidence-3-0-explained)
- Shopify Community anecdote (store launched Oct 2023): three fraudulent chargebacks in May 2024 pushed rate >1%; store lost Shop app eligibility, which requires chargeback rate <1% over six months measured from bank-decision date; merchant said Shopify's own risk indicators showed "low risk" and provided no support during disputes — [Shopify Community](https://community.shopify.com/t/chargeback/350299)

### Inferences
- Three different "fraud share" numbers coexist (NRF 9% of returns; LiquiDonate 15%; Riskified "1 in 4 refund dollars abusive"). The spread reflects definitions: "fraud" (empty box, counterfeit) vs "abuse" (wardrobing, bracketing, policy exploitation). A screener should score both buckets separately.
- The net-recovery figure (10.7%) vs first-cycle win (44.6%) implies dispute prevention (alerts, RDR, pre-dispute refunds) is worth more than representment for most SMBs.
- Loop's "11.4% of return value flagged high risk, $120 avg fraudulent return" is the most directly relevant Shopify-SMB benchmark.

### Gaps
- Could not retrieve the full 2026 Chargebacks911 Field Report (page content was empty) — sample size and per-industry win rates missing.
- Riskified's Jan 12, 2026 "1 in 4 refund dollars abusive" release (with any vertical/claim-type breakdown) returned 403/410; only the headline figure via PYMNTS is confirmed.
- No 2026-dated NRF/Appriss annual fraud dollar figure found (latest firm figure is 2024: $101–103B). NRF's Oct 2025 report gives a percentage (9%) not a dollar amount.
- Happy Returns/UPS and Narvar did not publish standalone 2026 fraud datasets I could find.

## Key Question 2: Mechanics — Visa CE 3.0, VAMP, Mastercard rules, Stripe/Shopify dispute flows, evidence packages, deadlines, what wins

### Takeaway
The dispute system is now explicitly data-matching driven: Visa CE 3.0 wins 10.4 fraud disputes by matching IP/device/account/address across two prior undisputed transactions, VAMP (1.5% merchant threshold since Apr 1, 2026, $8/item) punishes disputes received, not lost, and the practical merchant toolchain is Stripe's Dispute object (with CE 3.0 autofill) or Shopify's ShopifyPaymentsDispute object, with 4.5 MB / ≤50-page evidence packages and ~45-day representment windows on Mastercard.

### Cited Findings

**Visa Compelling Evidence 3.0 (CE 3.0)**
- Applies to Visa card-not-present disputes under reason code 10.4 "Other Fraud — Card-Absent Environment". Merchant must supply two prior undisputed transactions on the same payment credential, each 120–365 days before the dispute date, neither previously reported as fraud. Qualifying data elements: User/account ID, shipping address, IP address, device ID/fingerprint; at least two must match across all three transactions and at least one must be IP or device ID — [Chargebacks911](https://chargebacks911.com/prevent-chargebacks/prevent-visa-disputes/visa-compelling-evidence-3-0/); [Chargeflow](https://www.chargeflow.io/blog/visa-compelling-evidence-3-0-explained)
- Submission paths: pre-dispute via Verifi Order Insight (blocks the chargeback from being filed) or post-dispute via VROL representment — [Chargebacks911](https://chargebacks911.com/prevent-chargebacks/prevent-visa-disputes/visa-compelling-evidence-3-0/)
- Stripe's implementation detail: prior transactions must be 120–364 days old, paid, undisputed, not validation charges, and all processed by Stripe; must set `merchandise_or_services` and `product_description` for disputed and prior transactions. Evidence element table — Main: customer purchase IP; customer device fingerprint or device ID. Secondary: shipping address; customer email address; customer account ID. Must match two main elements, or one main + one secondary; "device fingerprint AND device ID" is not a valid combination — [Stripe CE 3.0 docs](https://docs.stripe.com/disputes/api/visa-ce3)
- Stripe API objects: `enhanced_eligibility_types: ["visa_compelling_evidence_3"]`; `evidence.enhanced_evidence.visa_compelling_evidence_3.{disputed_transaction, prior_undisputed_transactions[]}` with sub-fields `charge, customer_account_id, customer_device_fingerprint, customer_device_id, customer_email_address, customer_purchase_ip, shipping_address, merchandise_or_services, product_description`; `evidence_details.enhanced_eligibility.visa_compelling_evidence_3.{status (requires_action|qualified|not_qualified), required_actions[], partner_rejected_details}`; Stripe autofills from prior charges; test card 4000000404000038 — [Stripe CE 3.0 docs](https://docs.stripe.com/disputes/api/visa-ce3)
- 2025–2026 CE 3.0 timeline: Oct 2025 — automation/issuer-side enhancements (Visa Secure auto-qualification); Apr 18, 2026 — CE 3.0 extended to non-disputed fraud (undisputed TC40 fraud reports); Oct 24, 2026 — multi-merchant evidence: transactions at other merchants may be used as qualifying evidence for 10.4 — [Chargeflow](https://www.chargeflow.io/blog/visa-compelling-evidence-3-0-explained). A secondary source states Visa "attached a fee to successful qualifications in April 2026" — [cside](https://cside.com/blog/compelling-evidence-3-requirements-data-points) (conflict: Chargeflow describes the April 2026 change as TC40 coverage; fee claim not confirmed by a Visa primary source)

**Visa Acquirer Monitoring Program (VAMP)**
- Ratio = (TC40 fraud reports + TC15 non-fraud disputes) ÷ TC05 settled transactions, card-not-present only. Merchant threshold cut from 2.2% to 1.5% on Apr 1, 2026 (US, Canada, EU, APAC, LATAM; CEMEA stays 2.2%). Acquirer thresholds enforced from Jan 1, 2026: 0.5% "above standard", 0.7% "excessive". Fee ~$8 per fraud/dispute item; first violation in a 12-month rolling window gets a 3-month grace period before enrollment; US merchant "excessive" requires both ≥1.5% and ≥1,500 fraud+dispute items in a month — [Merchant Risk Council](https://merchantriskcouncil.org/learning/resource-center/member-news/blog/2026/stricter-vamp-ratio-thresholds-are-now-in-effect-heres-how-to-stay-compliant); [Chargeflow VAMP](https://www.chargeflow.io/blog/vamp-visa-acquirer-monitoring-program)
- What removes items from the VAMP ratio: Rapid Dispute Resolution (auto-refund by rule) removes the dispute entirely; a successful CE 3.0 pre-dispute match prevents both the dispute and the fraud report from counting; refunds issued on CDRN (Verifi) / Ethoca alerts mean no chargeback is filed — [Merchant Risk Council](https://merchantriskcouncil.org/learning/resource-center/member-news/blog/2026/stricter-vamp-ratio-thresholds-are-now-in-effect-heres-how-to-stay-compliant)
- Stripe: "the card networks don't consider how many disputes you win or lose, only how many you receive — a withdrawn dispute still counts as a dispute"; accepting a dispute does not change the dispute fee — [Stripe docs](https://docs.stripe.com/disputes/best-practices)

**Mastercard**
- Reason code 4837 "No Cardholder Authorization": cardholder has 120 days to file; merchant has 45 days to respond. Reason code 4853 "Cardholder Dispute" (not as described, not received, defective, counterfeit, credit not processed): 120-day filing window, extendable to 540 days from processing when delivery/services were delayed; merchant gets 45 days for representment — [Chargeflow Mastercard guide](https://www.chargeflow.io/blog/mastercard-chargeback-survival-guide); [Chargebacks911 Mastercard codes](https://chargebacks911.com/chargeback-reason-codes/mastercard/)
- Mastercard evidence file limit on Stripe: 19 pages (vs 4.5 MB for all networks) — [Stripe docs](https://docs.stripe.com/disputes/best-practices)
- Mastercard's Excessive Chargeback Merchant (ECM) thresholds apply regardless of whether a transaction was agent-initiated — [Chargeflow agentic regulation](https://www.chargeflow.io/blog/agentic-commerce-regulation-what-merchants-need-to-know)

**Stripe dispute flow and Dispute object**
- `Dispute` fields: `amount, charge, payment_intent, currency, reason, status, is_charge_refundable, balance_transactions[], enhanced_eligibility_types[], evidence{}, evidence_details{due_by, has_evidence, past_due, submission_count}, payment_method_details.card.network_reason_code, metadata`. `reason` enum: `bank_cannot_process, check_returned, credit_not_processed, customer_initiated, debit_not_authorized, duplicate, fraudulent, general, incorrect_account_details, insufficient_funds, noncompliant, product_not_received, product_unacceptable, subscription_canceled, unrecognized`. `status` enum: `warning_needs_response, warning_under_review, warning_closed, needs_response, under_review, won, lost, prevented`. `enhanced_eligibility_types`: `visa_compelling_evidence_3, visa_compliance, mastercard_compliance` — [Stripe Dispute object](https://docs.stripe.com/api/disputes/object)
- `evidence` hash fields: `access_activity_log, billing_address, cancellation_policy, cancellation_policy_disclosure, cancellation_rebuttal, customer_communication, customer_email_address, customer_name, customer_purchase_ip, customer_signature, duplicate_charge_documentation, duplicate_charge_explanation, duplicate_charge_id, product_description, receipt, refund_policy, refund_policy_disclosure, refund_refusal_explanation, service_date, service_documentation, shipping_address, shipping_carrier, shipping_date, shipping_documentation, shipping_tracking_number, uncategorized_file, uncategorized_text`. Updating any field submits the whole hash (use `submit=false` to stage) — [Stripe Dispute object](https://docs.stripe.com/api/disputes/object); [Stripe CE 3.0 docs](https://docs.stripe.com/disputes/api/visa-ce3)
- Evidence package constraints: only PDF/JPEG/PNG; combined ≤4.5 MB; <50 pages (19 for Mastercard); one file per evidence type (merge emails/texts into one `customer_communication` file); 12-pt font; US Letter/A4 portrait; issuers won't review illegible files — [Stripe docs](https://docs.stripe.com/disputes/best-practices)
- What Stripe says wins: for fraud — AVS match, CVC match, 3DS result, purchase IP matching the verified billing address, signed receipts (Stripe auto-includes AVS/CVC/IP); for not-received/unacceptable — proof of shipment and delivery with the full delivery address (city/ZIP alone is insufficient), explanation if ship-to name differs from cardholder; for refund disputes — screenshot of terms as presented at checkout with the relevant policy section only; for partial-refund over-disputes — amount, date and dashboard screenshot of the refund ("credit issued" response); documentation of the cardholder withdrawing the dispute or prior compensation is "discrediting evidence" — [Stripe docs](https://docs.stripe.com/disputes/best-practices)
- Stripe Radar Plus shows a win-likelihood score per dispute (only for credit-card disputes, not inquiries) — [Stripe docs](https://docs.stripe.com/disputes/best-practices)

**Shopify Payments dispute flow**
- `ShopifyPaymentsDispute` fields: `amount, disputeEvidence, evidenceDueBy, evidenceSentOn, finalizedOn, id, initiatedAt, legacyResourceId, order, reasonDetails, status, type` (type distinguishes inquiry vs chargeback). Queries: `dispute(id)`, `disputes(...)` filterable by ID range, status, initiation time. `ShopifyPaymentsDisputeEvidence` fields referenced include `customerEmailAddress, shippingDocuments, uncategorizedText, productDescription, accessActivityLog` — [Shopify dev docs](https://shopify.dev/docs/api/admin-graphql/latest/objects/ShopifyPaymentsDispute)
- Shop app eligibility requires chargeback rate <1% over six months, measured from the bank's decision date — [Shopify Community](https://community.shopify.com/t/chargeback/350299)

### Inferences
- A screener's single highest-leverage output is a per-order "CE 3.0 readiness" record: capture and persist `customer_purchase_ip`, a device fingerprint/ID, account ID, email, and shipping address at checkout for every order, because the matching rule requires an IP or device element and merchants cannot reconstruct this after the fact.
- Because VAMP counts received disputes, the screener should route likely-friendly-fraud orders into pre-dispute paths (refund on alert / RDR / Order Insight) rather than into representment.
- The Oct 24, 2026 multi-merchant evidence change means first-time buyers at a merchant can still qualify for CE 3.0 if the network sees prior history elsewhere; this partly closes the "first-time buyer = no history" hole that Modern Retail flagged for return claims.

### Gaps
- Adyen's dispute API/evidence flow was not researched (out of time budget).
- Shopify's exact dispute response deadline (from a primary Shopify Help doc) and the full `ShopifyPaymentsDisputeEvidence` field list were not retrieved; only partial fields were visible.
- Primary Visa rule documentation (Visa Core Rules) was not fetched; all CE 3.0/VAMP details come from processor and vendor summaries that are consistent with each other.
- The April 2026 CE 3.0 "fee" claim (cside) vs "undisputed TC40 coverage" (Chargeflow) could not be resolved against a Visa primary source.

## Key Question 3: Return abuse patterns and the signals that detect them

### Takeaway
The dominant 2025–26 patterns are overstated-quantity/empty-box/decoy returns, wardrobing, bracketing, item-not-received claims, and organized "refund-as-a-service" rings on Telegram; detection in practice relies on inbound package weight vs expected, carrier scan timing vs refund timing, return-rate/velocity thresholds per customer, address/device/payment linkage across accounts, first-time-buyer flags, and (new in 2026) forensic inspection of claim photos for AI generation.

### Cited Findings

**Patterns**
- NRF 2025: overstated quantity (71% of tracking retailers report increases), empty box / "box of rocks" (65%), decoy/counterfeit returns (64%) — [NRF](https://nrf.com/media-center/press-releases/consumers-expected-to-return-nearly-850-billion-in-merchandise-in-2025)
- Ringly's Shopify playbook names wardrobing, bracketing abuse, empty-box fraud (claiming shipment when box is empty/wrong item), receipt fraud (fake/stolen receipts) — [Ringly](https://www.ringly.io/blog/how-can-i-prevent-refund-fraud-on-shopify)
- Modern Retail (Mar 2, 2026): AI-generated damage photos (some with visible AI watermarks), fake UPS/USPS drop-off receipts, fabricated police reports for "lost" items, AI-crafted complaint emails, duplicated product images with added damage, altered return labels ("fake ID tracking", i.e., FTID); a Nike sneakers case >$600; Yofi CEO Jordan Shamir: "It's growing very, very quickly... from seeing it onesie-twosie to daily" — [Modern Retail](https://www.modernretail.co/technology/from-boll-branch-to-bogg-brands-are-battling-a-surge-of-ai-driven-return-fraud/)
- PYMNTS (Mar 3, 2026): consumers use free image generators to fabricate scratched electronics, cracked screens, torn fabric, uploaded through standard return portals; one $800,000 ring bought low-cost items, generated AI "broken" images, took instant refunds and kept goods — [PYMNTS](https://www.pymnts.com/news/retail/2026/ai-generated-damage-claims-trigger-retail-crackdown-on-return-fraud/)
- "Double-dip" (return refund plus chargeback on the same order) surfaces constantly in Shopify Community threads; auto-refund on carrier scan means money leaves days before warehouse inspection, and the chargeback window is still open when the discrepancy is found (as summarized) — [RefundSentry](https://refundsentry.com/return-fraud)
- Package redirection / FTID (fake tracking ID) scams: fraudster ships a different, often empty or near-empty, package so the carrier records a delivery under the retailer's return label — [Wikipedia: Package redirection scam](https://en.wikipedia.org/wiki/Package_redirection_scam)

**Refund-as-a-service / organized rings**
- Model: an operator on Telegram takes the customer's order info and makes the refund request (social engineering of customer service, empty-box or item-not-received claims) for a percentage or flat fee — [Chargebacks911](https://chargebacks911.com/organized-refund-fraud/)
- Amazon: sued groups Mario Refunds, A$O, Plugged, Kanan, Wave; disrupted REKK, Chin Chopa, Spectre, Noir's Luxury Refunds, Artemis Refund Group, Simple Refunds. REKK operator arrested in Lithuania (Mar 2025), €6M in assets seized, operated via Telegram and Reddit. DOJ "Operation Chargeback": Noir's Luxury Refunds had 5,900+ followers and claimed $1.2M processed; Artemis — 10 indicted across countries; Simple Refunds' Michigan operator sentenced to 3 years for $4M+ in retailer losses. Amazon invested >$1B in 2024 on fraud prevention with ML models analyzing "signals and data points" — [Amazon Trustworthy Shopping](https://trustworthyshopping.aboutamazon.com/inside-amazons-fight-against-refund-fraud)
- A prison term was handed down in a Telegram-based retail refund fraud scheme (May 5, 2026) — [Washington Times](https://www.washingtontimes.com/news/2026/may/5/prison-term-handed-telegram-based-retail-refund-fraud-scheme/) (headline only; article body returned 403)
- DOJ press releases on Noir's Luxury Refunds exist but returned empty bodies — [DOJ NDAL sentencing](https://www.justice.gov/usao-ndal/pr/members-noirs-luxury-refunds-telegram-channel-sentenced-prison); [DOJ WDWA](https://justice.gov/usao-wdwa/pr/second-defendant-charged-fraudulent-refund-scheme-targeting-online-retailers)

**Detection signals used by merchants**
- Boll & Branch: physical signs in photos — "unnatural cotton fraying patterns," dry boxes despite claimed liquid damage, duplicated corner nicks across images, tears inconsistent with product construction; CEO Scott Tannen: damage "did not look like anything cotton does when it frays." Countermeasures: FaceTime verification, purchase/return history monitoring, warehouse inspection before refund. Bogg: requires physical return for suspicious claims, standardized response language for manipulated images. Other flags: missing proof of purchase, first-time-buyer pattern — [Modern Retail](https://www.modernretail.co/technology/from-boll-branch-to-bogg-brands-are-battling-a-surge-of-ai-driven-return-fraud/); [PYMNTS](https://www.pymnts.com/news/retail/2026/ai-generated-damage-claims-trigger-retail-crackdown-on-return-fraud/)
- PYMNTS: merchants analyze claim patterns, customer history, and image metadata before approving refunds; risk-based (tiered) policies replacing uniform rules; UPS (Happy Returns) deployed AI-based inspection in the 2025 holiday season — [PYMNTS](https://www.pymnts.com/news/retail/2026/ai-generated-damage-claims-trigger-retail-crackdown-on-return-fraud/)
- Weight: a return that should weigh 2 kg scanning at 200 g on the inbound scan reveals empty-box fraud before opening (as summarized) — [RefundSentry](https://refundsentry.com/return-fraud)
- Practical thresholds: flag customers whose return rate exceeds 30–40%; require photos before approving returns; unique tags/seals to deter wardrobing; item-level return limits per customer; monitor patterns across accounts; Shopify Flow to tag repeat returners and route suspected abuse to a review queue; Shopify Return Rules (Settings > Policies) for windows, shipping, restocking fees — [Ringly](https://www.ringly.io/blog/how-can-i-prevent-refund-fraud-on-shopify); [Riskified Shopify guide](https://www.riskified.com/learning/shopify/shopify-fraud-prevention-apps-2026/)
- Third-party Shopify return-fraud apps analyze IP, geolocation, browser data, and policy rules by product type — [Forthroute](https://forthroute.io/blog/platforms-automatically-flag-suspicious-return-patterns-free-for-shopify)
- Device intelligence signal families (vendor framing): browser/device setup, network/location (IP, ASN, VPN/Tor/emulator), environment integrity, behavior/session, relationships and velocity (linked accounts) — [Fingerprint](https://fingerprint.com/blog/power-of-smart-signals-fraud-detection-prevention/)
- Item-level fingerprinting: Entrupy captures a unique imaging "fingerprint" at sale and rescans on return to confirm the same physical item came back (luxury/sneakers) — [Entrupy](https://www.entrupy.com/return-fraud-detection/)
- Carrier tracking data available to merchants: tracking responses include package `weight` and `weightUOM`, full scan event history with timestamps/locations, standardized event codes including "Return - Shipped to Retailer (RTS)", and USPS `scanType`/`l1Code` event codes — [Pitney Bowes tracking API docs](https://docs.shippingapi.pitneybowes.com/api/get-tracking.html); [Pitney Bowes event codes](https://docs.shippingapi.pitneybowes.com/reference/tracking-codes.html)
- Signifyd Return Abuse Prevention (launched Apr 2021) scores return requests low/moderate/high risk with recommendations on whether/how to process — [Signifyd](https://www.signifyd.com/news-releases/signifyd-return-abuse-prevention/); Forter claims 6,000+ data points, behavioral biometrics, 1.2B+ identities, covering transaction fraud, ATO, and policy abuse — [Ringly Forter alternatives](https://www.ringly.io/blog/forter-alternatives)

### Inferences
- A practical signal taxonomy for a screener, derived from the above: (1) customer history: return rate, refund-$/order-$ ratio, prior "item not received"/"damaged" claims, account age, first-order flag; (2) order: high-resale-value SKU, bracketing (multiple sizes/colors of one product), ship-to ≠ billing, gift-name mismatch; (3) identity linkage: shared device fingerprint/IP/address/payment across accounts; (4) logistics: carrier scan present or absent, scan-to-refund gap, inbound weight vs expected SKU weight, label/tracking ID mismatch (FTID), delivery address vs return origin; (5) claim artifacts: photo EXIF/metadata, duplicated image regions, generator watermarks, receipt authenticity; (6) velocity: claims per address/device per 30 days; (7) double-dip: an open return/refund plus a dispute on the same `charge`.
- The empty-box, FTID and double-dip patterns are the only ones fully detectable from logistics data alone; wardrobing and AI-photo fraud require inspection or image forensics.

### Gaps
- No public, quantified detection-rate data for weight-delta or scan-timing rules was found; the weight example is anecdotal.
- No source gave a canonical list of UPS/USPS/FedEx "return received" event codes beyond the Pitney Bowes RTS code.
- Could not access DOJ releases to confirm fee structures of refund-as-a-service operators (Chargebacks911 describes "percentage or set fee" generically).

## Key Question 4: What has changed with AI agents (Muse, Dots, ChatGPT; protocols; new network rules)

### Takeaway
As of Oct 2026, shopper-side agents (Meta Muse, launched Sep 8, 2026; OpenAI Dots, launched Sep 30, 2026) explicitly "handle refunds/returns," Meta's Link wallet backs shoppers with $250/item return protection and up to $1,000 if a merchant refuses, and 50% of consumers already use GenAI to draft claims — but I found no evidence that any agent auto-files card chargebacks, and the card networks have shipped agent identity/mandate rails (Visa TAP, Mastercard Agent Pay/Agentic Tokens, AP2, ACP/SPTs) without yet publishing binding agent-specific chargeback reason codes; disputes on agent orders still run through the human-era rules and monitoring programs.

### Cited Findings

**Shopper-side agents**
- Meta Muse launched Sep 8, 2026; 2.5M US shoppers installed it within weeks (app, web, WhatsApp). It "browses, completes forms, places orders, negotiates prices, and manages refunds," requires shopper approval before purchasing, and accesses only connected accounts with read-only or read-and-act permissions — [GSPANN](https://www.gspann.com/insights/blog/ai-shopping-agents-retailer-terms)
- Muse "shops, negotiates and handles returns, and pays through Link and Shop Pay" — [Tom's Guide](https://www.tomsguide.com/ai/meta-muse-vs-chatgpt-dots-i-compared-the-new-ai-agents-and-theyre-not-as-similar-as-they-look)
- Return protection on Muse purchases via Meta Link: returns covered up to $250 per item, refunds up to $1,000 if a merchant refuses a return within 60 days; GSPANN warns "AI agents make initiating returns almost effortless, increasing fraud risk" — [GSPANN](https://www.gspann.com/insights/blog/ai-shopping-agents-retailer-terms)
- OpenAI Dots launched the week of Sep 30, 2026 as always-on agents with their own cloud computers/browsers that can shop; announced less than a day after OpenAI delayed GPT-6.1 Astra — [TechSpot](https://www.techspot.com/news/114043-openai-takes-meta-muse-always-dots-agents-less.html); [CNBC](https://www.cnbc.com/2026/09/30/openai-follows-meta-into-the-red-hot-market-for-personal-agents.html)
- Amazon blocked Muse from browsing/purchasing on Sep 20, 2026, alleging Muse accessed the store without notice or authorization, does not identify itself when browsing, and captures/stores customer logins; Amazon is also working to block Google and OpenAI agents. Meta partnered with Walmart, GameStop, Sephora, Expedia, OpenTable and Shopify; Best Buy, Gap, Wayfair also named — [Campaign](https://www.campaignlive.com/article/amazon-blocks-metas-muse-shopping-its-platform/1970733); [Bloomberg](https://www.bloomberg.com/news/articles/2026-09-21/amazon-blocks-meta-s-muse-ai-agent-from-its-retail-site); [GSPANN](https://www.gspann.com/insights/blog/ai-shopping-agents-retailer-terms)
- Shopify auto-enrolled eligible stores into Muse checkout with a 7-day opt-out window — [GSPANN](https://www.gspann.com/insights/blog/ai-shopping-agents-retailer-terms); [ALM Corp](https://almcorp.com/news/meta-muse-shopify-checkout-access-amazon-blocks-ai-agent/)
- Adoption context: only 5% of consumers have authorized agents to place orders independently; AI-referred retail visits converted 54% better than standard traffic (Adobe, May 2026); Salesforce projects agents will originate 20% of holiday e-commerce traffic — [GSPANN](https://www.gspann.com/insights/blog/ai-shopping-agents-retailer-terms)
- GSPANN recommends retailers set five agent terms: agent identity verification, shopper mandate limits, secure payment rails, customer data handling, post-sale (returns) policies; cites Visa TAP and Cloudflare Web Bot Auth for cryptographic agent verification — [GSPANN](https://www.gspann.com/insights/blog/ai-shopping-agents-retailer-terms)

**Consumers using AI (not necessarily agents) to file claims**
- 50% of consumers use GenAI tools (ChatGPT, Claude) to draft return/refund claims; retail leaders say shoppers write "highly convincing return requests" that overwhelm teams (Riskified, Jun 22, 2026) — [StockTitan/Riskified](https://www.stocktitan.net/news/RSKD/return-abuse-goes-mainstream-as-nearly-half-of-consumers-use-ai-in-zigrxun82sxl.html)
- 65% of consumers say AI made it easier to falsely claim refunds for items they own; shoppers feed real product photos into ChatGPT/Gemini to add cracks, tears, stains; AI also generates fake UPS/USPS drop-off receipts (as summarized from Modern Retail/Riskified coverage) — [Modern Retail](https://www.modernretail.co/technology/from-boll-branch-to-bogg-brands-are-battling-a-surge-of-ai-driven-return-fraud/)
- Academic: "Generative AI-Enabled Refund Fraud in Chinese E-Commerce: Investigation on Merchants and Platform Workers" (arXiv, Jun 2026) documents the same pattern on Chinese platforms — [arXiv](https://arxiv.org/pdf/2606.03215)

**Card-network and protocol rules for agent-initiated transactions**
- Visa Intelligent Commerce announced Apr 30, 2025; Visa Trusted Agent Protocol (TAP) formally launched Oct 14, 2025 with Cloudflare: agent identity is signed into HTTP request headers with public-key cryptography and merchants verify against Visa's directory; Visa pilot partners include Anthropic, OpenAI, Microsoft, Stripe, Adyen — [eco.com comparison](https://eco.com/support/en/articles/15192003-mastercard-agent-pay-vs-visa-trusted-agent-2026-compared); [Nuvei](https://www.nuvei.com/posts/nuvei-supports-visa-trusted-agent-protocol-to-advance-agentic-commerce)
- TAP data elements: agent intent, consumer recognition, payment information — "a cryptographically verifiable record of who approved what, when, and through which agent" — but "agent identity and mandate data won't appear in clearing data or dispute evidence overnight"; no new reason codes or agent identifiers in dispute evidence yet; expect more "unauthorised" claims with insufficient evidence and ambiguous fraud/non-fraud categorization — [Rivero](https://rivero.tech/blog/agentic-commerce-disputes-liability)
- Visa's model includes an agent-as-merchant-of-record option: the agent platform settles with the underlying merchant, "owns first-line disputes," and the merchant is shielded from friendly fraud; Visa flow uses per-transaction signed intents the merchant validates via directory lookup — [eco.com comparison](https://eco.com/support/en/articles/15192003-mastercard-agent-pay-vs-visa-trusted-agent-2026-compared)
- Visa threat view (Nov 20, 2025): agent impersonation of trusted brands, agents deceived by counterfeit merchants after purchasing with stored credentials; controls = TAP identity fields, time-based challenges, telemetry into Visa fraud models — [Visa Perspectives](https://corporate.visa.com/en/sites/visa-perspectives/security-trust/the-threats-landscape-of-agentic-commerce.html)
- Mastercard Agent Pay announced Apr 29, 2025: registered, verified agents transact via Mastercard Agentic Tokens (MDES-based); the authorization message carries the Agentic Token plus an agent-flag indicator; mandates (spend ceilings, MCCs, time windows, recurring rules) are set at token provisioning and validated by the issuer in real time; pilot partners Microsoft, IBM, Braintree, Checkout.com. For fraud, liability follows standard tokenized-transaction rules (issuer liable when token validly issued); consumer chargeback rights remain intact — [eco.com Agent Pay](https://eco.com/support/en/articles/15192001-what-is-mastercard-agent-pay-ai-agent-commerce-protocol-in-2026); [eco.com comparison](https://eco.com/support/en/articles/15192003-mastercard-agent-pay-vs-visa-trusted-agent-2026-compared)
- Mastercard "Verifiable Intent" (2026, per a secondary source): issuer-signed intent credentials travel with the transaction; merchants receive MCC scope, spending caps, validity windows (max 7 days), geographic scope, and credential reference IDs; two new dispute grounds — unauthorized agent action within a mandate, and repudiation of the mandate itself — said to route to the agent operator in most cases; within-mandate transactions get card-present-like liability protection — [Digital Applied](https://www.digitalapplied.com/blog/mastercard-verifiable-intent-trust-agentic-commerce) (secondary source; Mastercard primary page returned 403 — treat specifics as unconfirmed)
- Chargeflow: "neither [Visa nor Mastercard] has published a binding chargeback rule for agent disputes"; where an agent authenticates and a token is validly issued, liability follows authenticated tokenized rules; "everything short of outright fraud" is murky — [Chargeflow AI agent liability](https://www.chargeflow.io/blog/ai-agent-chargeback-liability)
- Google Agent Payments Protocol (AP2) launched Sep 16, 2025 (Google, Mastercard, PayPal; FIDO-governed): signed Checkout Mandates and Payment Mandates (open = standing constraints; closed = finalized checkout) as cryptographic proof of consumer consent — [Chargeflow agentic regulation](https://www.chargeflow.io/blog/agentic-commerce-regulation-what-merchants-need-to-know); [eco.com comparison](https://eco.com/support/en/articles/15192003-mastercard-agent-pay-vs-visa-trusted-agent-2026-compared)
- OpenAI/Stripe Agentic Commerce Protocol (ACP) released Sep 29, 2025 under Apache 2.0; Shared Payment Tokens (SPTs) are scoped to a specific seller, bounded by time and amount, and observable through their lifecycle; the merchant remains merchant of record and "retains all control over... how refunds and disputes are managed"; Stripe Radar relays risk signals (likelihood of fraudulent dispute, card testing, stolen card) on SPT charges; Stripe Agentic Commerce Suite launched Dec 11, 2025 (product discovery endpoint, Checkout Sessions, SPT processing) — [Stripe blog](https://stripe.com/blog/agentic-commerce-suite); [eco.com ACP](https://eco.com/support/en/articles/14845478-acp-agentic-commerce-protocol-explained)
- SPT "protects the consumer's credentials but does little to protect the merchant from intent disputes" — if the agent buys the wrong product, the merchant of record likely eats the return and chargeback — [FinTech Wrap Up](https://www.fintechwrapup.com/p/deep-dive-the-hidden-liability-of)
- Google + Shopify Universal Commerce Protocol (UCP) covers discovery, cart and checkout across AI surfaces; American Express "Agent Purchase Protection" covers erroneous registered-agent purchases — [Chargeflow agentic regulation](https://www.chargeflow.io/blog/agentic-commerce-regulation-what-merchants-need-to-know); [Chargeflow AI agent liability](https://www.chargeflow.io/blog/ai-agent-chargeback-liability)
- Evidence gap on agent orders: device fingerprints unavailable (API, not browser), no browsing history or session behavior, IP belongs to the AI platform's servers not the customer — exactly the elements CE 3.0 relies on. Recommended: log agent identifiers, authorization mandates, session tokens, interaction timestamps; log agent-initiated transactions separately; VAMP/ECM apply regardless of initiation method — [Chargeflow AI agent liability](https://www.chargeflow.io/blog/ai-agent-chargeback-liability); [Chargeflow agentic regulation](https://www.chargeflow.io/blog/agentic-commerce-regulation-what-merchants-need-to-know)
- Regulation: Reg E "does not clearly resolve whether agent authorization counts as consumer consent"; no US federal framework; EU AI Act high-risk provisions delayed to Dec 2027 — [Chargeflow agentic regulation](https://www.chargeflow.io/blog/agentic-commerce-regulation-what-merchants-need-to-know)
- Monitoring: "card network monitoring programs do not distinguish between human-initiated and AI-initiated disputes" — [Chargeflow agentic regulation](https://www.chargeflow.io/blog/agentic-commerce-regulation-what-merchants-need-to-know)

### Inferences
- Two distinct agent-era threats for a merchant screener: (a) consumer-side GenAI "claim polishing" and fake evidence (already mainstream — 50% of consumers), and (b) autonomous agents (Muse/Dots) initiating returns/refund requests at near-zero effort, backed by wallet-level return guarantees that give consumers an incentive to escalate when a merchant declines. The second is weeks old and un-measured.
- Meta Link's "$1,000 refund if merchant refuses a return within 60 days" effectively creates a second adjudication layer outside the card networks; merchants should expect Meta/Link to request evidence of policy compliance much like an issuer does.
- On protocol-compliant agent orders (ACP/SPT, Agent Pay, TAP), the mandate/intent record is the replacement for IP/device evidence; the screener should persist the signed intent, token scope, agent ID and agent-flag at order time, because Rivero/Chargeflow both note it is not yet carried in clearing/dispute data.
- Amazon's Sep 2026 block shows the large-merchant reflex is to refuse unidentified agents; SMBs on Shopify were auto-enrolled, so they are the population most exposed to agent-initiated returns without the tooling.

### Gaps
- I found no documented case of Muse, Dots, ChatGPT or any agent auto-filing a card chargeback on a consumer's behalf, nor any merchant reporting agent-originated return/dispute volumes; all "agents will file disputes at scale" claims are forward-looking.
- Meta's own documentation of Link return protection terms (the $250/$1,000 figures) was not accessible (CNN 451, eMarketer 403); figures rest on GSPANN's summary.
- No published Visa or Mastercard rule text with agent-specific dispute reason codes; the "two new dispute grounds" come from a secondary blog.
- Whether Shopify or Stripe expose an "agent-originated" flag on `Order`/`Charge` objects to merchants is undocumented in the sources I reached (Stripe's suite announcement names no field).

## Key Question 5: Vendor landscape — what tools do and don't do, pricing, enterprise vs SMB gap

### Takeaway
Enterprise fraud platforms (Signifyd, Riskified, Forter, Sift) now bundle "policy abuse" / returns scoring but are quote-priced percent-of-GMV products aimed at larger merchants; chargeback automation (Chargeflow, Chargebacks911) is contingency-priced and SMB-accessible but reactive; returns platforms (Loop, Narvar, Happy Returns) add risk flags and workflows; Shopify's native stack offers rules, Flow and risk-assessment objects but no returns-abuse scoring — leaving SMBs with the "double-dip," AI-photo and agent-claim problems largely unaddressed.

### Cited Findings
- Signifyd: charges a percentage of each approved order, varying by product, vertical, volume, average ticket; no public starting price; Return Abuse Prevention (Apr 2021) sizes the problem at $43B and assigns low/moderate/high risk with processing recommendations; later expanded into an "Intelligent Returns Suite" — [Redo pricing comparison](https://redo.com/resources/articles/comparisons/fraud-platform-pricing); [Signifyd release](https://www.signifyd.com/news-releases/signifyd-return-abuse-prevention/); [Future Market Insights](https://www.futuremarketinsights.com/reports/returnless-refund-fraud-detection-market)
- Riskified: performance pricing from ~0.4% per transaction, quoted on volume and risk; Dynamic Returns (Jan 12, 2026) is a Policy Protect feature applying differentiated return treatment by risk profile; Riskified case study claims a luxury brand cut chargebacks from ~$1M to $150–200K/yr (75% reduction) and raised approval from ~50% to 75–80% — [Redo pricing](https://redo.com/resources/articles/comparisons/fraud-platform-pricing); [PYMNTS](https://www.pymnts.com/news/retail/2026/ai-generated-damage-claims-trigger-retail-crackdown-on-return-fraud/); [Riskified Jan 2026 release](https://www.businesswire.com/news/home/20260112619982/en/Riskified-Analysis-Reveals-1-in-4-Refund-Dollars-Is-Abusive-Introduces-Dynamic-Returns-a-New-Policy-Protect-Feature-to-Safeguard-Revenue-While-Increasing-Customer-Satisfaction); [StockTitan/Riskified](https://www.stocktitan.net/news/RSKD/return-abuse-goes-mainstream-as-nearly-half-of-consumers-use-ai-in-zigrxun82sxl.html)
- Forter: no public pricing, enterprise model "starting in the thousands per month"; covers transaction fraud, ATO, policy abuse with 6,000+ data points and 1.2B+ identities — [Redo pricing](https://redo.com/resources/articles/comparisons/fraud-platform-pricing); [Ringly](https://www.ringly.io/blog/forter-alternatives)
- Chargeflow (SMB/Shopify-focused): 25% of each recovered chargeback (no monthly fee, no contract), $29 per deflected chargeback via alerts, $0.20 per scanned transaction after the first 1,000 for fraud screening — [Redo Chargeflow alternatives](https://redo.com/resources/articles/comparisons/chargeflow-alternatives-shopify)
- Redo's view: most merchants under ~$1M/yr do not need a dedicated fraud platform — [Redo pricing](https://redo.com/resources/articles/comparisons/fraud-platform-pricing)
- Chargebacks911: 69% of merchants in its 2026 survey rely only on in-house staff for representment; 34% use Ethoca/Verifi alerts — [Chargebacks911 stats](https://chargebacks911.com/chargeback-stats/)
- Loop Returns: flags high-risk returns before refund (11.4% of return value flagged; $120 avg fraudulent return), supports fees, exchange-first, Shop Now; integrates with Happy Returns drop-off — [Loop](https://www.loopreturns.com/reports/retention-benchmarks-2026/); [Loop Happy Returns integration](https://docs.loopreturns.com/integration-guides/happy-returns)
- Narvar: "Narvar Shield" launch cited as AI-driven policy orchestration; Narvar positions returns as a revenue function — [Future Market Insights](https://www.futuremarketinsights.com/reports/returnless-refund-fraud-detection-market); [PYMNTS](https://www.pymnts.com/news/retail/2026/ai-generated-damage-claims-trigger-retail-crackdown-on-return-fraud/)
- Happy Returns (UPS): co-authored NRF 2025 report; UPS deployed AI-based inspection in 2025 holiday season — [NRF](https://nrf.com/research/2025-retail-returns-landscape); [PYMNTS](https://www.pymnts.com/news/retail/2026/ai-generated-damage-claims-trigger-retail-crackdown-on-return-fraud/)
- Emerging mid-market tools named by Modern Retail: Yofi (fraud prevention), Order Protection (shipping insurance), Two Boxes (returns processing/inspection) — [Modern Retail](https://www.modernretail.co/technology/from-boll-branch-to-bogg-brands-are-battling-a-surge-of-ai-driven-return-fraud/)
- Shopify native: Return Rules (windows, shipping, restocking fees), return window overrides by market/collection/product/variant (shortest matching window wins), Shopify Flow for return-abuse workflows (tag repeat returners, route to review), self-serve returns; `OrderRiskAssessment` with `riskLevel`, `facts[]`, `provider` and the `orderRiskAssessmentCreate` mutation (fires `orders/risk_assessment_changed` webhook) lets apps inject their own risk facts — [Shopify changelog](https://changelog.shopify.com/posts/return-window-overrides-now-available); [Riskified Shopify guide](https://www.riskified.com/learning/shopify/shopify-fraud-prevention-apps-2026/); [Shopify dev docs](https://shopify.dev/docs/api/admin-graphql/latest/objects/OrderRiskAssessment)
- Amazon: ML models over "signals and data points," >$1B invested in 2024, litigation against refund groups — [Amazon](https://trustworthyshopping.aboutamazon.com/inside-amazons-fight-against-refund-fraud)
- Community sentiment: a Shopify Community poster alleged coordination between fraudsters and chargeback-app vendors charging 25% of disputed amounts (unverified accusation, included as sentiment) — [Shopify Community](https://community.shopify.com/t/chargeback/350299)

### Inferences
- The gap for SMBs: nothing in the stack correlates the three event streams (return request → carrier/warehouse receipt → payment dispute) for one order; fraud platforms score at checkout, returns apps score at the return request, chargeback apps act after the dispute. A screener that joins them and watches for the double-dip and scan-vs-refund timing is not offered natively.
- Enterprise vendors' percent-of-GMV pricing plus sales-led onboarding make them impractical for a hackathon or sub-$1M merchant; Chargeflow-style contingency pricing is the comparable go-to-market for an SMB screener.

### Gaps
- Sift, Ravelin, Chargebacks911, Narvar, Happy Returns pricing not found.
- Returnly was not covered (it was folded into Affirm/Loop ecosystems years ago; no 2026 product data found).
- No independent evaluation of any vendor's AI-photo detection accuracy.

## Key Question 6: Data an SMB merchant can realistically access to build a screener (Shopify, Stripe, carriers, email)

### Takeaway
A Shopify + Stripe (or Shopify Payments) merchant can get everything needed for a first screener from four sources: Shopify Admin GraphQL (Order, Return, ReverseFulfillmentOrder, OrderRiskAssessment, ShopifyPaymentsDispute), Stripe Disputes API (with CE 3.0 autofill and evidence hash), carrier tracking APIs (scan events, weight), and support email/photo attachments — the main blind spot is checkout-time device/IP capture, which must be instrumented in advance.

### Cited Findings
- Shopify `Return` object: `id, name, status (ReturnStatus), order, createdAt, closedAt, requestApprovedAt, staffMember, totalQuantity, returnLineItems, exchangeLineItems, refunds, reverseFulfillmentOrders, returnShippingFees, suggestedFinancialOutcome`; scopes `read_returns` or `read_marketplace_returns`; mutations `returnRequest` (customer request needing approval), `returnCreate`, `returnApproveRequest`, `returnDeclineRequest`, `returnProcess` (returns, exchanges, dispositions, refunds) — [Shopify dev docs](https://shopify.dev/docs/api/admin-graphql/latest/objects/Return)
- Shopify returns API lets partners display third-party RMAs in Shopify with real-time status — [ReturnGO](https://support.returngo.ai/shopify-returns)
- Shopify `OrderRiskAssessment`: `facts[] (RiskFact), provider (App or null for Shopify), riskLevel (RiskAssessmentResult)`; `OrderRiskSummary.assessments`; scope `read_orders`; `orderRiskAssessmentCreate` mutation + `orders/risk_assessment_changed` webhook — [Shopify dev docs](https://shopify.dev/docs/api/admin-graphql/latest/objects/OrderRiskAssessment)
- Shopify `ShopifyPaymentsDispute`: `amount, disputeEvidence, evidenceDueBy, evidenceSentOn, finalizedOn, initiatedAt, order, reasonDetails, status, type`; `disputes` query filterable by status and initiation time — [Shopify dev docs](https://shopify.dev/docs/api/admin-graphql/latest/objects/ShopifyPaymentsDispute)
- Stripe `Dispute` object, `evidence` hash, `evidence_details.due_by`, `enhanced_evidence.visa_compelling_evidence_3` (autofilled when Stripe processed the prior charges), file limits 4.5 MB / <50 pages / PDF-JPEG-PNG, one file per evidence type, `submit=false` staging — [Stripe Dispute object](https://docs.stripe.com/api/disputes/object); [Stripe CE 3.0](https://docs.stripe.com/disputes/api/visa-ce3); [Stripe best practices](https://docs.stripe.com/disputes/best-practices)
- Stripe auto-captures AVS/CVC results and purchase IP "if available from your Stripe integration" — "The more information your integration collects and passes to Stripe when your customer makes a payment, the better your ability to... challenge" — [Stripe best practices](https://docs.stripe.com/disputes/best-practices)
- Carrier tracking APIs expose `weight`/`weightUOM`, full scan-event history with timestamps and locations, standardized event codes (e.g., RTS "Return - Shipped to Retailer"), and USPS `scanType`/`l1Code` — [Pitney Bowes](https://docs.shippingapi.pitneybowes.com/api/get-tracking.html); [Pitney Bowes codes](https://docs.shippingapi.pitneybowes.com/reference/tracking-codes.html); UPS Developer APIs knowledge base — [UPS](https://www.ups.com/assets/resources/media/Developer_APIs_Knowledge_Base.pdf)
- Shopify Flow can tag repeat returners and route suspected abuse to a review queue without code — [Riskified Shopify guide](https://www.riskified.com/learning/shopify/shopify-fraud-prevention-apps-2026/)

### Inferences
- Minimum viable screener data model (all obtainable above): per `Order` — customer ID/email, billing/shipping addresses, AVS/CVC, purchase IP (Stripe `charge`), line items/SKU weights, fulfillment tracking numbers; per `Return` — reason, requested/approved timestamps, return label tracking, photos from the return portal/email; per carrier event — first-scan time, delivery time, package weight; per `Dispute` — reason, network reason code, `due_by`, CE 3.0 eligibility; plus derived features (return rate, scan-to-refund gap, weight delta, double-dip, address/device reuse).
- Agent-originated orders will lack a usable IP/device; the screener should treat "no device fingerprint + API checkout" as a distinct class and store any agent/mandate identifiers available from the checkout channel.

### Gaps
- Full `ReturnStatus` enum values, `ReturnReason` enum values, and `ReverseFulfillmentOrder` disposition fields were not captured (page excerpt truncated).
- Did not verify whether Shopify exposes checkout IP/device data to apps (Shopify's own risk "facts" may embed it, but the field list was not retrieved).
- No primary UPS/USPS/FedEx API field documentation for inbound return weight at first scan was retrieved; Pitney Bowes docs show weight is a standard tracking field but coverage per carrier is unverified.
